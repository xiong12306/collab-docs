**版本**：v1.0  
**产品经理**：许清楚（Xu）

**语言**：中文

---

## 1. 项目信息

| 项目 | 内容 |
|------|------|
| 项目名称 | `collab-docs` |
| 技术栈 | React + Next.js App Router + Ant Design |
| 后端 | Next.js API Routes |
| 数据库 | Supabase（免费版） |
| 鉴权 | JWT（自定义实现） |
| 实时协同 | Supabase Realtime（WebSocket）|
| 协同算法 | OT（Operational Transformation）/ CRDT |
| 富文本编辑器 | Tiptap（优先，支持协同扩展）|

**原始需求**：构建最小化多用户文档协作系统，参考飞书文档/腾讯文档核心功能，支持多人同时编辑、实时光标同步、文档权限管理。

---

## 2. 产品目标

> **一句话目标**：让多人能够实时协同编辑同一文档，像本地编辑一样流畅，像飞书文档一样简单。

**核心价值主张**：

1. **实时协同**：多用户同时编辑，冲突自动合并，光标可见，零延迟感知
2. **权限清晰**：owner / editor / viewer 三级权限，文档分享精准可控
3. **开箱即用**：最小化复杂度，注册即可创建/分享文档，无需学习成本

## 3. 用户故事

### P0（MVP 核心）

| # | 用户故事 |
|---|----------|
| US-01 | As a **新用户**，I want 注册账号并登录，so that 能够创建和管理我的文档 |
| US-02 | As a **文档 owner**，I want 创建/删除文档并邀请他人协作，so that 能够发起团队写作 |
| US-03 | As a **协作者**，I want 与其他用户同时编辑同一文档并看到彼此光标，so that 能够高效协作不互相覆盖 |

### P1（第二阶段）

| # | 用户故事 |
|---|----------|
| US-04 | As a **文档 owner**，I want 设置协作者为 editor 或 viewer 权限，so that 能够精确控制谁能编辑、谁只能查看 |
| US-05 | As a **任意用户**，I want 查看文档的历史版本，so that 能够在误操作后恢复内容 |

### P2（未来迭代）

| # | 用户故事 |
|---|----------|
| US-06 | As a **editor**，I want 在文档内@提及其他成员，so that 能够精准触达协作者注意力 |
| US-07 | As a **viewer**，I want 对文档内容添加评论，so that 能够在不修改原文的情况下反馈意见 |

## 4. 核心需求池

### P0 — MVP 必须有

| ID | 需求 | 说明 |
|----|------|------|
| P0-01 | 用户注册 / 登录 | 邮箱+密码，JWT 签发与校验 |
| P0-02 | 创建 / 删除文档 | owner 操作，文档标题可编辑 |
| P0-03 | 文档列表页 | 区分"我的文档"与"共享给我"两类 |
| P0-04 | 富文本编辑器（Tiptap） | 支持基础格式：H1-H3、粗体、斜体、列表、引用 |
| P0-05 | **多人实时协同编辑** | OT/CRDT + Supabase Realtime，冲突自动合并 |
| P0-06 | **多人光标显示** | 显示其他在线用户的光标位置与用户名（不同颜色区分） |
| P0-07 | 文档分享（邀请链接 / 邮箱） | 生成链接或按邮箱邀请，默认 editor 权限 |
| P0-08 | 三级权限控制 | owner / editor / viewer，控制编辑和管理操作 |

### P1 — 第二阶段

| ID | 需求 | 说明 |
|----|------|------|
| P1-01 | 历史版本记录 | 按时间保存快照，支持查看与回滚 |
| P1-02 | 权限管理 UI | owner 可在文档内调整协作者权限或移除成员 |
| P1-03 | 在线状态指示 | 文档顶部头像列表显示当前在线协作者 |
| P1-04 | 文档重命名 | 内联编辑标题，实时同步 |

### P2 — 未来迭代

| ID | 需求 | 说明 |
|----|------|------|
| P2-01 | 行内评论 | 选中文字添加评论，类 Google Docs |
| P2-02 | @提及通知 | 文档内@用户，触发站内通知 |
| P2-03 | 文档模板 | 预置空白/会议记录/需求文档等模板 |
| P2-04 | 导出 PDF / Markdown | 一键导出文档内容 |

**多人协同交互说明**：
- 每位在线用户分配唯一颜色，光标位置和选区实时同步
- 用户名气泡跟随光标显示（悬浮 1.5s 后淡出）
- 顶部右上角头像列表实时展示当前在线用户（最多显示 5 个，超出折叠）
- 断线自动重连，重连后 OT/CRDT 进行状态对齐

## 6. 待确认问题

| # | 问题 | 影响方向 | 优先级 |
|---|------|----------|--------|
| Q1 | **OT vs CRDT**：Tiptap 官方协同方案基于 Yjs（CRDT），是否直接采用 `@tiptap/extension-collaboration` + `y-supabase` 方案，而非手写 OT？ | 协同算法选型 & 实现复杂度 | 🔴 P0 |
| Q2 | **Supabase Realtime 方案**：使用 Broadcast 频道广播操作（低延迟）还是 Postgres Changes 监听（强一致）？两者对协同体验差异明显 | 实时通信架构 | 🔴 P0 |
| Q3 | **JWT 存储方式**：localStorage（简单，有 XSS 风险）还是 httpOnly Cookie（安全，需处理跨域）？Next.js App Router 下 cookie 方案更自然 | 鉴权安全性 | 🟡 P1 |
| Q4 | **文档内容存储格式**：Tiptap JSON（Prosemirror 格式）还是 HTML string？JSON 更便于版本 diff，HTML 更通用 | 数据库 Schema 设计 | 🟡 P1 |
| Q5 | **历史版本策略**：按操作步骤记录（存储压力大）还是按时间间隔快照（实现简单）？MVP 阶段建议每 5 分钟快照 | P1 历史版本功能范围 | 🟢 P2 |
| Q6 | **Supabase 免费版限制**：Realtime 并发连接 200 上限，免费版数据库 500MB，是否在 MVP 阶段满足需求？是否需要设计连接复用或离线缓存降级 | 系统扩展性 & 稳定性 | 🟡 P1 |
